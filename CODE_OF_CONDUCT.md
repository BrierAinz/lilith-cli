# Code of Conduct

Lilith CLI is a technical project. Discussion should stay useful, evidence-based, and focused on improving the software.

## Expected behavior

Contributors and maintainers are expected to:

- Critique code, designs, evidence, and decisions rather than people.
- Provide enough technical context for others to reproduce or evaluate a claim.
- Keep review comments specific and actionable.
- Respect privacy and never publish credentials, personal data, private prompts, or unrelated local material.
- Accept that maintainers may narrow scope, reject unsafe changes, or request stronger verification.
- Attribute upstream work, third-party code, research, and borrowed ideas accurately.

## Unacceptable behavior

The project does not accept harassment, threats, discriminatory abuse, deliberate disruption, impersonation, doxxing, credential exposure, or knowingly misleading technical claims.

## Enforcement

Maintainers may edit, hide, lock, or remove contributions and participation that violate these expectations. Repeated or severe violations may result in temporary or permanent restrictions from project spaces.

Security vulnerabilities must follow [SECURITY.md](SECURITY.md) rather than public issue or discussion channels.

## Scope

This policy applies to repository issues, pull requests, reviews, discussions, and other project spaces controlled by the maintainers.
