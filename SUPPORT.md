# Support

Lilith CLI is maintained as an open-source technical project. Use the repository's existing GitHub surfaces so questions, bugs, and security reports reach the right place.

## Bugs

Open a **Bug report** issue when you can reproduce incorrect behavior.

Include:

- operating system and Python version;
- Lilith version or commit;
- the smallest reproducible command/workflow;
- expected and observed behavior;
- sanitized logs or traceback when relevant.

Do not include API keys, tokens, private prompts, personal data, private repository contents, or workstation-specific credentials.

## Feature requests

Use the **Feature request** issue form for a focused proposal. For substantial architectural changes, explain the use case and the capability/security boundary before implementation work begins.

## Questions

Use the **Question** issue form for repository-specific usage or development questions that are not security-sensitive.

## Security

Do **not** report vulnerabilities through a normal issue, discussion, pull request, or public log. Follow [SECURITY.md](SECURITY.md) and use GitHub's private vulnerability reporting flow.

## Scope

Support covers the standalone public `BrierAinz/lilith-cli` repository and its documented public interfaces.

Private Yggdrasil infrastructure, private account routing, workstation-specific privileged launchers, private transports, and unrelated BrierStudios systems are outside this repository's public support surface.

There is no guaranteed response-time SLA.
